# 本地资料与阶段衔接

本文件是入行适配的执行规则，优先于随包上游文档中示范的作者路径、默认资料目录和索引写回位置。上游正文保留方法与版式要求，不能按其中旧路径写个人资料。

## 数据根目录

以本包 `SKILL.md` 所在目录为项目根，不依赖 shell 当前目录。未指定数据目录时用 `<项目根>/.career-data/`；用户指定其他本地目录时使用该目录。脚本统一用 `--data-dir` 显式传递该绝对路径。项目内自定义目录必须位于 `.career-data/` 内；也可使用项目外目录。先告知实际保存位置，用户已指定路径时直接沿用。

| 内容 | 相对于数据根目录 |
|---|---|
| 用户确认的个人资料（沿用 resume-data 字段） | `profile/resume-data.md` |
| 搜索清单、分析报告、简历打印/编辑版、比较与谈薪报告 | `reports/`，保留原模块文件名规则 |
| JD 记录与索引 | `jd-bank/` |
| 真实故事与索引 | `story-bank/` |
| Offer 与谈薪记录 | `offer-bank/`、`deal-bank/` |
| 申请记录的唯一真相源 | `applications.json` |
| 实际提交快照 | `applications/<申请ID>/submitted/<快照ID>/` |

源模块里的 `jd-bank/`、`story-bank/`、`offer-bank/`、`deal-bank/` 仅供读取模板与标注示例。所有用户记录和 `_index.md` 写到上表中的运行时位置。跨模块读取也使用这个数据根。模板、框架、图片仍从各 Skill 源目录读取，不能把运行数据路径用作模板路径。

## 旧资料

首次使用先只读检查原模块资料目录；优先运行 `python3 <项目根>/tools/migrate_legacy.py --dry-run --data-dir <数据根>`。真正需要旧资料时执行同命令去掉 `--dry-run`，复制并校验，不删除源文件。同名不同内容报告冲突，原文件均保留，核对后选择需要的版本。原目录仍可只读检索；运行目录已有同名记录时优先使用运行目录，迁移冲突不能静默当作已解决。

迁移排除上游原样示例和 `_index.md`；新建 `_legacy-index.md` 仅登记实际复制的记录。旧索引有个人条目而正文缺失时报告缺失，不重建个人经历。源目录中的示例人物、薪资、收益、匹配率都不能成为用户事实。

## 申请上下文

使用 `application-tracker-skill/scripts/tracker.py read` 读取，按申请 ID 关联，不能仅凭公司名称把两次申请合并。提交归档使用用户确认的实际文件；已有归档禁止覆盖，新提交形成新快照。先 `verify` 核验再用于面试。

当前简历可继续编辑；提交快照只读。缺少提交材料明确告知，用户可以提供准确版本后追加归档，不能猜测补齐。求职信为可选材料，本轮不引入第二套简历或评分流程。

## 原有内容兼容

旧模板 `resume-skill/templates/tech-compact.html` 继续可用，按原有 schema 渲染；不作为默认模板。现有 HTML 与 PDF 不修改。新报告仍遵守各模块的双语、署名与交互要求，验收演示必须显著标注合成资料/模拟 Offer。

保留报告的作者署名、品牌与社交链接；页脚中的资料来源、方法和“已核验”声明要按本次真实执行填写。没有查过 Levels.fyi、没有拿到招聘官原话时，不能原样保留模板中相应的来源声明。没有校准数据时不输出面试概率，未知市场分位留为未知。报告里的复制按钮应在剪贴板不可用时提供手动复制反馈；不能静默失效。
